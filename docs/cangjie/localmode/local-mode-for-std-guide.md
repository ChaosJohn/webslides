# 标准库适配 local mode 策略规则指南

> 用途：评审被问"为什么要加这个适配"时，先按签名形态查 §4 速查表拿到规则编号，再到 §3 看两句话理由。
> 全文不假设读者懂 local mode。官方术语与白话对照见 §6。

## 1. 需要提前知道的 4 件事

**① 三种状态。** 一个对象关于"区域"只有三种可能状态：

| 本文叫法 | 官方写法 | 含义 |
|---|---|---|
| 普通对象 | `~local`（无标注） | 常规堆对象，谁都能引用，与区域无关 |
| 区域内 | `@local!` | 对象在某个区域内，区域销毁时随之回收；**它引用到的所有数据也都在区域内** |
| 不确定 | `@local?` | 可能是区域内、也可能是普通对象，二者皆可 |

**② 三条硬规则。** 下文所有策略规则都从这三条推出来，评审追问到底时回到这里：

1. **强可以当弱用**：`@local!` 的值传给 `@local?` 参数、赋给 `@local?` 变量，免费合法（官方名：降级）。
2. **弱换强必须复制**：把"不确定"变成"区域内"，唯一办法是复制一份新数据；内容不可复制的对象复制不出来，运行时也没有手段"测一下它到底在不在区域内"。
3. **参数模式决定门宽**：参数标 `@local!` 只收"区域内"实参；标 `@local?` 三种都收；无标注只收普通对象（原方法只服务原有世界）。

**③ Copyable。** 内容能逐字节复制出独立副本的类型：数值、Bool、Rune、由它们组成的 struct 等。**String、Array、类实例都不是**。可复制值在三种状态间转换无成本、无约束。

**④ 容器的承诺覆盖它装的东西**（官方名：深模式继承）。"区域内"的容器，它装的每个元素、每个可达对象都必须在区域内；从"不确定"的容器里取出来的东西，也只能算"不确定"。=> 装不可复制元素的容器，构造和写入的门槛都由元素决定。

## 2. 总纲：看签名只看两个旋钮

- **参数模式 = 门宽**：决定谁能调用、什么数据能传进来。
- **结果模式 = 声称**：返回值说"我在区域内"，这句话必须为真；说不出来就只能标"不确定"。

每个适配决策 = 两个旋钮各拧到哪一档，理由最终都落到 §1② 的三条硬规则。

## 3. 规则卡片

### 规则 1：每个适配类型必加"区域内"构造函数

```cangjie
public init(this @local!)
public init(this @local!, capacity: Int64)   // 带可复制参数的变体同理
```

- 为什么：区域内代码要创建该类型实例，区域内必须"造得出来"。这是其他一切适配的前提。
- Array / ArrayList / String / HashMap 均已补。

### 规则 2：元素来源构造，按"元素能不能复制"决定要不要 @local? 版本

从别的集合装内容来构造（`init(elements:)`）：

- 元素**不保证可复制**（泛型 T、类实例）→ 必须加宽门版本，否则这类来源永远装不进容器：

  ```cangjie
  public init(this @local!, elements: Collection<T> @local!)   // 区域内容器只收区域内元素
  public init(this @local?, elements: Collection<T> @local?)   // 宽门：接住不确定来源，结果如实不确定
  ```

- 元素**可复制** → 不需要 `@local?` 版本（可复制值自由转换，`@local!` 构造 + 降级已覆盖）。
- ⚠️ 禁止出现 `init(this @local!, elements: Collection<T> @local?)`：区域内容器从不确定来源装不可复制元素，是对 §1④ 承诺的撒谎。
- 内容级来源（拷字节的互转构造）不适用本条，见规则 6。

### 规则 3：读取类方法——结果是"取出来的东西"且不可复制 → 双版本

`get`、下标 `[]`、`slice`、`clone`、`splitAt`、`iterator` 等返回对象内部数据的方法：

```cangjie
public func get(this @local!, key: K @local?): Option<V> @local!   // 区域内接收者：结果保住区域内身份
public func get(this @local?, key: K @local?): Option<V> @local?   // 不确定接收者：结果如实不确定
```

- 为什么：结果与接收者**共享**数据，结果的承诺强度只能跟接收者一样（强了是撒谎，弱了丢信息）；两版本互不可替代——`@local?` 接收者调不了 `@local!` 版本（门宽，硬规则 3），`@local!` 接收者走 `@local?` 版本会拿到丢失"区域内"身份的结果。
- 是否"共享"的判定见规则 7。

### 规则 4：判定/计数类——结果是纯可复制值 → 只留 @local? 单版本

`contains`、`isEmpty`、`indexOf`、`prop size` 等：

```cangjie
public func contains(this @local?, key: K @local?): Bool
```

- 为什么：可复制结果与模式无关（§1③），一个版本对三种接收者交付完全等价的东西；`@local!` 版本是重复品，不提供。

### 规则 5：写入类——只有 @local! 版本

`add`、`set`、下标赋值 `[]=`、`remove`、`clear`、`fill`、`copyTo` 等：

```cangjie
public func add(this @local!, key: K @local!, value: V @local!): Option<V> @local!
public operator func [](this @local!, index: Int64, value!: T @local!): Unit
```

- 为什么：往"可能是普通对象"的容器里写区域内的数据，区域销毁后普通对象还引用着它 → 悬垂引用。所以写入只对确定的区域内实例开放。
- 返回被删除/被覆盖旧值的（`remove`/`add`），旧值是元素读出，结果模式随接收者锁死（规则 3 同理）。

### 规则 6：不共享的完整复制——单版本：接收者放宽 @local?，结果取 @local!

方法把内容**逐字节/逐元素复制**出一份全新数据（内容可复制才做得到）：字符串互转构造、拷字节的 `toArray`/`toRuneArray`。

```cangjie
public func toArray(this @local?): Array<Byte> @local!   // 一个版本通吃三种接收者
```

- 为什么：复制出来的数据是真新数据，"在区域内"的声称永远为真、与接收者无关；接收者放宽让三种调用方都能用。
- 与规则 3 的分界线见规则 7。

### 规则 7：共享三分法（规则 3 与规则 6 的分界线）

判断"结果与接收者共享什么"，**看实现，不看方法名**：

1. **视图**（切片、迭代器、entryView）：共享底层存储 → 共享 → 规则 3。⚠️ 反例警示：`Array.slice` 源码是 `Array(this.rawptr, ...)`，零拷贝视图，不是拷贝。
2. **容器拷贝**（`clone`）：新底层存储，但元素引用共享（元素不可复制时只能如此）→ 仍算共享 → 规则 3。
3. **内容复制**（逐字节/逐元素复制且内容可复制）→ 不共享 → 规则 6。

### 规则 8：参数模式按用途标

- **只读用途**（查找键、比较、只读来源）→ `@local?`：不产生存储，宽门无害。例：`get`/`contains` 的 `key: K @local?`。
- **会被存进对象** → `@local!`：数据生命周期从此与对象绑定，承诺必须一致（§1④）。例：`add` 的 key 和 value——**key 是被存储的**，与 `get` 的只读 key 形成对照；upsert 型下标赋值同理。
- **可复制参数** → 不标（自由转换）。例：`capacity: Int64`、`index: Int64`。

### 规则 9：prop 是单旋钮

prop 的模式标注只改变 getter 的接收者模式，返回值模式不单独拧：

- 返回可复制值 → 单版本 `@local?`（规则 4）。例：`public prop size: Int64 @local?`。
- 返回元素/子容器（不可复制）→ 按规则 3 出双版本 prop。例：ArrayList 的 `first`/`last`。

### 规则 10：可复制元素的写入扩展

"不确定"实例上要写入时，用泛型扩展补，不污染主签名：

```cangjie
extend<R> Array<R> where R <: Copyable {
    public operator func [](this @local?, index: Int64, value!: R): Unit
}
```

- 为什么：可复制的值写进任何容器都不产生共享、不破坏任何承诺（§1③④）。

### 规则 11：不适配清单（评审问"为什么这个没适配"）

- **unittest**：测试代码世界本来就是普通对象世界，无区域可谈。
- **fs / io**：OS 资源句柄（文件描述符等），不参与区域回收。
- **Copyable 类型与 VArray**：可复制值三种状态等价，模式无信息量。
- **跨界交互**：区域内外数据交换靠"复制型入口"，如 `String.fromUtf8(bytes): String @local!`——普通字节复制成区域内字符串。

### 规则 12：表达力边界（诚实声明，评审常问）

不可复制元素 + 区域内容器：**区域外的来源数据进不来**（硬规则 2：不能升级）。出路三选一：

1. 在区域内就地生产数据（初始化 lambda、区域内构造的字符串）；
2. 元素可复制时免费转换（Copyable 值随意进出）；
3. 走规则 2 的宽门构造（共享元素引用，结果如实为"不确定"）。

## 4. 评审速查表

| 被问到的签名形态 | 依据 | 一句话理由 |
|---|---|---|
| `init(this @local!)` | 规则 1 | 区域内造不出来，一切免谈 |
| `init(this @local?, elements ... @local?)` | 规则 2 | 元素不可复制时这是唯一入口 |
| get/[]/slice/clone/splitAt/iterator **双版本** | 规则 3+7 | 结果与接收者共享 → 承诺锁死 → 两版互不可替代 |
| contains/isEmpty/indexOf/prop size **只有 @local?** | 规则 4 | 可复制结果与模式无关，强门版本是重复品 |
| add/set/[]=/remove/copyTo **只有 @local!** | 规则 5 | 写区域数据进普通对象 = 悬垂风险，禁止 |
| toArray/字符串互转：`this @local?` + 结果 `@local!` **单版本** | 规则 6 | 完整复制断开共享，新数据声称区域内永远为真 |
| 参数 `@local?`（只读）/ `@local!`（存储）/ 不标（Copyable） | 规则 8 | 用途决定门宽 |
| prop `: Int64 @local?` | 规则 9 | 单旋钮 |
| extend + where Copyable 的 setter | 规则 10 | 可复制值写入不产生共享 |
| 某类型没有适配 | 规则 11 | 测试框架 / OS 句柄 / 可复制类型不在射程内 |
| "为什么区域外的数据加不进区域内容器" | 规则 12 | 不可复制来源不能升级，见三条出路 |

## 5. 常见追问

**Q1：为什么 slice 要双版本，而单元素 get 的 `@local!` 版本反而删了？**
单元素 get 返回可复制值（规则 4：`@local?` 单版本通吃）；slice 返回不可复制的视图（规则 3+7：共享锁死 → 双版本）。同一把尺子，结果类型不同、结论不同。

**Q2：为什么 String 的 toArray 单版本，Array 的 toArray 却要双版本？**
String.toArray 拷字节，内容可复制 → 不共享 → 规则 6；Array.toArray 元素可能不可复制 → 元素引用共享 → 规则 3。

**Q3：为什么 add 的 key 要 `@local!`，get 的 key 却是 `@local?`？**
规则 8：add 会存储 key（upsert 的下标赋值还可能插入新键），get 只读 key。

**Q4：为什么不提供"把不确定的对象升级成区域内"的运行时检查？**
硬规则 2：升级的唯一语义是复制；不可复制对象复制不出来，运行时也没有模式信息可查。需要区域内版本的数据，必须在区域内生产或复制出来。

**Q5：为什么不给"区域内"构造函数配"不确定"的 elements 参数？**
§1④：区域内容器装的元素必须区域内；来源是不可复制元素时引用会被共享，声称"区域内"就是撒谎。区域内容器只收区域内元素，宽门由 `this @local?` 版本承担（规则 2）。

## 6. 术语对照

| 官方/文档用语 | 白话 |
|---|---|
| `~local` / 无标注 | 普通对象 |
| `@local!` | 区域内（强承诺，覆盖全部可达数据） |
| `@local?` | 不确定（弱承诺） |
| 降级 | 强当弱用，免费 |
| 升级 | 弱换强，唯一途径是复制 |
| 深模式继承 | 容器的承诺自动覆盖它装的所有东西 |
| 视图 | 共享底层存储的"窗口"（slice、迭代器） |
| Copyable | 内容可逐字节复制的类型 |
| `@Frozen` | ABI 冻结标注；适配采取"新增方法"形态，不改已有签名，不影响冻结 |

> 完整改动清单与逐签名判定注释见《标准库适配 local mode 策略问题闭环.md》§3.4.1–3.4.4（Array / ArrayList / String / HashMap）。

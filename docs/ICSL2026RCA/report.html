03
Attack Path Matrix

攻击路径与影响矩阵

#9 HTTP chunked 属于 1:1 攻击——攻击者需付出与服务器相当的资源成本，攻击价值低，影响程度评定为"低"。

04
Category A

A类：无攻击路径（4个）

代码质量缺陷、协议兼容性问题或错误路径资源管理缺陷，通常在异常触发条件下导致功能异常或进程崩溃。

#3 cjdb — int8_t 循环变量溢出

类型不匹配导致有符号/无符号比较异常。当 typeArgNum > 127 时，int8_t 循环变量溢出为负数，触发无限循环和越界读取。同一文件存在第二处相同模式漏洞。

#4 std — IPv6 解析协议不兼容

未按 RFC 4291 实现，错误拒绝合法的 x:x:x:x:x:x:d.d.d.d 形式（6 个 hextet + 末尾嵌入 IPv4）。系统 inet_pton 接受该格式，标准库解析器不兼容。

#7 stdx — algorithm 对象泄漏

EncryptPrivateKey 中 PKCS8_set0_pbe 失败时仅释放 p8info，algorithm 对象未释放，造成内存泄漏。属于错误路径资源管理缺陷。

#8 stdx — SM3 悬空指针二次释放

reset() 的 catch 分支释放 sm3Ctx 后未置空，调用者捕获异常并保留对象时，析构器仍看到非空悬空指针并再次释放，导致堆损坏。

05
Category B

B类：有攻击路径但需本地权限或高条件（4个）

存在理论攻击路径，但利用需要本地代码执行权限、对目录结构的感知、竞态条件命中或内存转储能力等较高前提。

#1 Macro — FlatBuffers Verifier 缺失

需 LSP 模式 + 本地 LD_PRELOAD 注入宏服务器进程，通过 IPC 管道注入恶意 FlatBuffers。全代码库 VerifyMacroMsgBuffer 调用次数为 0，对比其他模块有 Verifier。攻击价值较小。

#5 std — 符号链接跟随 (TOCTOU)

realpath() 返回 ENOENT 时回退到原始 path，open() 未加 O_NOFOLLOW。需本地权限并在 realpath 与 open 的竞态窗口内替换文件为符号链接，无稳定攻击路径。

#6 stdx — 加密路径密码未清零

用户密码通过 mallocCString 复制到堆缓冲区，C 函数使用后未清零，free() 后密码字节残留在已释放堆块中。需通过内存转储（core dump / swap / 堆检查）恢复。解密路径有 memset_s，加密路径没有——非对称遗漏。

#10 stdx — Tar 解压父级符号链接越界

Tar.extract 在覆写删除之前未校验解析后的父级路径是否仍在解压根内。先删除后校验，词法校验无法解析已存在的父级符号链接。需本地权限感知目录结构，在解压根下预置或竞态植入父级符号链接。

06
Category C

C类：有攻击路径且远程可达或需用户交互（2个）

可通过网络远程触发或通过诱导用户交互触发，攻击面较广。

#2 HLE — 注释闭合突破注入
  • addComment 函数将不可信输入包裹在 /*${msg}*/ 中但不转义 */
  • class 属性值含 */ 时注释提前闭合，后续内容变为可执行代码
  • 关键发现：恶意代码写入静态构造函数后，无需主动调用即可自动执行
  • 需用户使用 HLE 工具处理恶意 .d.ts 文件，HLE 使用场景有限
#9 stdx — HTTP chunked 绕过大小限制
  • 仅当请求携带 Content-Length 时才校验 maxRequestBodySize
  • chunked 分支直接进入 body provider，provider 仅累计字节数从不与限制比较
  • 未认证客户端可经 Transfer-Encoding: chunked 流式发送任意大小请求体
  • 1:1 攻击范畴：攻击者消耗的带宽/资源与服务器相当，攻击效率低，需大量并发才能造成显著影响
07
Root Cause Analysis

回溯分析：模型组合与围栏应对差异

我们（ICSL 介入前）
  • 模型：GPT 5.5 + Claude Opus 4.6/4.7/4.8
  • Claude 可用性：很差，经常遇到安全围栏
  • 围栏应对：无应对策略，被围栏阻断即放弃
  • 工具：cangjie-vuln-hunter、cangjie-compiler-vuln-hunter、audit-lite
ICSL
  • 模型：GLM 5.1 + GPT 5.6
  • 模型能力：GPT 5.6 能力更强
  • 围栏应对：遇到安全围栏后，通过越狱手段得以突破
  • 工具：无特殊工具，复用我们的 Skills

核心结论：工具相同（复用我们的 Skills），唯一可确定的变量是模型组合（GPT 5.5 vs GPT 5.6/GLM 5.1）和围栏应对策略（无应对 vs 越狱突破）。模式库匹配差距是现象描述，而非根本原因。

08
Root Cause Analysis

回溯分析：问题定级标准差异

案例1：#9 HTTP chunked
  • 我们的判定：1:1 攻击模式，攻击者消耗与服务器相当的资源，攻击价值低 → 非问题
  • 与蓝军讨论：一致认为 1:1 模式不构成有效威胁
  • ICSL 的判定：1:1 也是问题，级别较低；如果是 1:N 则为严重或致命问题
  • 差异本质：对"攻击效率比"的定级阈值不同
案例2：#2 HLE 注释闭合注入
  • 我们的判定：开发者应对工具自动生成的代码负责 → 非问题，甚至不用修复
  • 与蓝军讨论：一致认为责任在开发者侧
  • ICSL 的判定：工具本身应保证生成代码的安全性 → 严重问题
  • 差异本质：对"代码生成工具安全责任边界"的认定不同
09
Root Cause Analysis

回溯分析：问题探索深度差异

我们（防守方）
  • 确认 #2 HLE 注释闭合问题存在
  • 判断注入的恶意代码不会被主动调用
  • 结论：无有效的攻击路径
  • 倾向于常规利用路径下判断问题严重性
ICSL（攻击方）
  • 投入较多精力单点对该问题进行探索和钻研
  • 发现把恶意代码写在静态构造函数里
  • 静态构造函数无需主动调用，也会自动执行
  • 会探索非常规利用路径，深挖问题潜力

核心差异：防守方倾向于在常规利用路径下判断问题，攻击方会投入精力探索非常规利用路径。对同一个问题的探索深度不同，导致对"是否存在有效攻击路径"的结论不同。

10
Test Coverage Gap

测试看护分析：为什么没有看护住

反序列化校验缺失

#1 Macro FlatBuffers Verifier 缺失。现有测试覆盖正常序列化/反序列化流程，但未覆盖恶意输入校验场景。对比其他模块有 Verifier，说明该模块测试用例未对齐安全基线。

错误路径测试不足

#7 对象泄漏、#8 二次释放均发生在错误/异常路径。现有测试主要覆盖正常执行路径，对失败回退、异常捕获后的资源清理缺乏系统性测试。

协议符合性测试缺失

#4 IPv6 解析未按 RFC 4291 实现。现有测试覆盖常见格式，但未覆盖 RFC 允许的全部合法格式，特别是 IPv4 嵌入形式等边缘格式。

安全编码规范执行

#3 类型不匹配（int8_t vs uint8_t）、#5 缺少 O_NOFOLLOW、#6 密码未清零。这些属于安全编码规范范畴，但现有代码审查和静态分析未能有效拦截。

边界条件测试

#9 HTTP chunked 绕过大小限制。现有测试覆盖 Content-Length 分支的大小限制，但未覆盖 chunked 编码分支的相同限制，说明测试用例未覆盖所有代码路径。

竞态条件测试

#5 TOCTOU、#10 Tar 符号链接竞态。竞态条件需要精确时序控制才能触发，常规功能测试难以覆盖，需要专门的并发/竞态测试框架。
